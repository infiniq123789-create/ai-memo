# 시나리오 01: 메모 작성

- **우선순위:** P0 (핵심 기능, 다른 시나리오의 선행 조건)
- **대상 URL:** http://localhost:3000
- **탐색 일자:** 2026-10-16 (Playwright MCP로 직접 확인)

## 목적

사용자가 새 메모를 작성하면 저장되어 목록 최상단에 나타나는지 검증한다.

## 사전 조건

- 개발 서버 실행 중 (`npm run dev`)
- 메모 목록이 로드된 상태 (기준 데이터: "총 6개의 메모")

## 테스트 단계

| # | 동작 | 셀렉터 (Playwright) | 기대 결과 |
| - | ---- | ------------------- | --------- |
| 1 | 페이지 접속 | `page.goto('/')` | 헤더에 "📝 우람이", 탭 제목 "우람이" |
| 2 | "새 메모" 클릭 | `getByRole('button', { name: '새 메모' })` | "새 메모 작성" 모달 표시 |
| 3 | 제목 입력 | `getByRole('textbox', { name: '제목 *' })` | 입력값 반영 |
| 4 | 내용 입력 | `getByRole('textbox', { name: '내용 *' })` | 입력값 반영 (마크다운 에디터) |
| 5 | "저장하기" 클릭 | `getByRole('button', { name: '저장하기' })` | 모달 닫힘 |

## 검증 항목

- 목록 최상단에 입력한 제목의 메모 카드가 표시된다.
- 카테고리 기본값은 "개인"이다.
- 메모 개수 표시가 "총 6개의 메모"에서 "총 7개의 메모"로 증가한다.

## 테스트 데이터

- 제목: `E2E 탐색용 메모`
- 내용: `탐색용 내용입니다.`

## 비고 / 주의

- 메모는 Supabase에 저장되므로 테스트 후 반드시 삭제(시나리오 03)하여 데이터를 정리한다.
- 제목·내용은 필수(`*`) 항목이다. 빈 값 저장 시 동작은 별도 시나리오(P1)로 분리한다.
